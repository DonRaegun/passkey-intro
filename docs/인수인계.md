## 지금 상태

**만들어 둔 것**
- 공개 소개 페이지(대표 프로젝트 4개: 가계부, 품질 회수 판단, JARVIS(개발 중), 로얄 카지노) + 비공개 영역(패스키 로그인).
- 서버(`server.js`): 등록·로그인·로그아웃·비공개 자료·패스키 목록/삭제·접근 차단. 저장소는 axhub PostgreSQL.
- 비공개 자료: 계정 순번(seed)으로 가져옴. 첫 계정 6건, 둘째 7건 (모두 `[가상]` 표시).
- 화면의 "접근 차단 확인" 칸: 상대 계정 이름을 넣고 요청해 403·건수를 보여 줌.
- 안드로이드 삼성 인터넷의 출처(`android:apk-key-hash:`)도 허용.

**시험 (모두 통과)**
- `node test/verify.js <주소>`: 소프트웨어 인증기로 서버 로직 18개 → 기록 `test/evidence.txt`
- `node test/e2e.js <주소>`: 가상 인증기로 화면 전체 흐름 22개 → 기록 `test/e2e-evidence.txt` (`npm i playwright-core` 필요, 서버는 새 DB로)
- 배포 주소 읽기 전용 확인: 데스크톱·폰 폭 모두 정상, `/api/private` 401

**실제 계정 (배포 서버)**: `ghs`(자료 6건), `gong`(자료 7건). 각각 폰 패스키 "Mobile" 1개(Samsung Pass).

## 조건 달성 현황 요약

- **달성**: C10, C11, C13~C19, C21, C24, C25, C27, C29, C34~C36, C43, 그리고 폰 캡처로 C26(Samsung Pass), C37·C39·C40 일부(ghs→gong 방향)
- **증거만 모으면 됨**: C38(gong→ghs 반대 방향), C42·C44·C45(두 번째 패스키와 삭제), C46(마지막 하나 삭제 거절 화면)
- **글로 적으면 됨**: C12, C20, C22, C23, C28, C30~C33, C41, C47~C53 → 대부분 `docs/T08-제출문.md`와 설명서에 초안이 있음
- **제출 폼 입력**: C01~C03 (URL 두 개)

## 집에서 할 일 (순서대로)

1. **C38**: 폰에서 `gong`으로 로그인 → 맨 아래 "접근 차단 확인"에 `ghs` 입력 → 요청 보내기 → 캡처. (403, 요청 전후 건수 7건 그대로)
2. **두 번째 패스키 (C42)**: 폰의 **크롬 앱**으로 페이지를 열고 `gong` 또는 `ghs`로 로그인 → "새 패스키 이름" → "패스키 추가 등록". 같은 폰의 삼성 인터넷으로 만든 것과 다른 저장소(구글 비밀번호 관리자)가 되면 성공. "이미 등록된 패스키"가 뜨면 같은 저장소라는 뜻이니 집 PC(Windows Hello)나 다른 기기를 쓰세요. 등록 때 뜨는 창에 저장 위치가 나오니 캡처.
   - 집 PC에서는 "저장 위치"를 "이 기기(Windows Hello·PIN)"로 고르면 됩니다.
3. 목록에 두 줄 보이는 화면 캡처 (C43).
4. 하나 삭제 → 로그아웃 → 남은 패스키로 로그인 (C44). 삭제한 패스키로는 로그인 안 되는 문구 캡처 (C45: "등록되지 않았거나 삭제된 패스키입니다").
5. 마지막 하나 삭제 시도 → "마지막 패스키는 지울 수 없습니다" 캡처 (C46).
6. `docs/T08-제출문.md`의 `[직접 채우기]`(두 번째 패스키 저장 위치)와 "AI와 내 판단 3줄"이 사실과 맞는지 확인하고 고치기.
7. 새 시크릿 창에서 결과물 URL과 소스 URL이 열리는지 확인 후 제출 폼에 입력.

## 이어서 작업할 때 (집 PC)

```bash
git clone https://github.com/DonRaegun/passkey-intro.git
cd passkey-intro
npm install
node server.js          # http://localhost:3000 (WebAuthn은 localhost에서 동작)
node test/verify.js http://localhost:3000   # 새 DB(data.json 지운 뒤)에서 실행
```

- `data.json`은 로컬 전용 저장 파일이고 저장소에는 올라가지 않습니다(.gitignore).
- 배포 서버에서 `verify.js`·`e2e.js`를 돌리면 시험 계정이 서버에 남습니다(삭제 기능 없음). 제출용 계정 두 개가 흐려지니 로컬에서만 돌리세요.
